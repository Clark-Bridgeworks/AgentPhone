AGENTPHONE · AB COMMUNICATION BRIDGE 0.4.7

只架桥，由两边的 Agent 工作

连接 → 转发 → 显示 → 返回。A/B 是两个连接位置，可以接入不同 Agent；它们保持自己的会话。

普通使用：三步

  1. 双击 AgentPhone.exe。等顶部检测到本机 Agent。窗口只有左右两侧会话视图和桥状态，没有任务输入框。
  2. 在你原来正在使用的 Agent 里下命令。例如：“请和 DeepSeek 讨论一下，然后一起完成这个需求。”新对话会根据本机全局说明使用 AgentPhone，不需要每次手把手教接入命令。需求仍然交给原 Agent。
  3. 让当前 Agent 调用桥的 send_message。桥遵守“选择两边对话”中的设置。选择已有 B 时使用它的原对话；选择新 B 或尚未指定时，首次真实消息送达会创建并打开原软件的新对话。后续消息持续使用同一连接和原生会话。

以本机 Codex 与 DeepSeek 为例：对当前 Codex 说“通过 AgentPhone 联系 DeepSeek，告诉它：我们正在测试通信桥，请回复通信桥收到。”当前 Codex 接入 A 端，DeepSeek 在 B 端创建新会话，原 DSH 窗口自动切换到这个对话。你可以直接在 DSH 看它收到的消息和回复。无需在 AgentPhone 输入工作任务。

本版按你的纠正执行：新对话必须出现在目标原桌面软件的界面。不是只在桥里显示一栏，也不是后台另起一个看不见的 DSH 会话。选择新对话时只创建一次，选择已有对话则沿用原对话；后续消息复用它。原计划中禁止所有原 Agent GUI 操作的条款已按此要求修订。

选择两边已有或新对话

点击“选择两边对话”。A、B 分别选软件和“已有对话 / 新对话”；已有对话显示原名称、项目和会话 ID。A 新对话在应用时打开原软件空对话，由你在原软件提出需求；B 新对话在首次收到真实消息时创建并打开。桥不启动任务或调用模型来测试接入。

“断开连接”保留原上下文；“续接原对话”恢复同一连接。选回同一对原对话也会自动续接。真正丢失的对话或不能唯一识别的同名窗口会报错，不新建替代。其他没有原桌面接口的目标仍禁止连接。

继续保留：桥不按三分钟取消工作

DSH、Codex 桌面适配器取消整轮三分钟时限。DSH 通过工具确认收到后，桥即可继续投递，不必等它做完整项工作。工具等待 25/30 秒只影响本次收信等待，不会取消原 Agent。

短暂状态读取失败会重试只读查询；连续读不到状态会明确报监测故障，但不取消 DSH。关闭桥、开窗失败和协议错误也不会取消原 DSH。原任务由原软件管理；旧版中断的任务不会自动重发。

继续保留的功能

DSH 可见消息显示中文来源和正文；内部协议移到它原生加载的工作区指令文件，不再往聊天正文塞大段英文。中文内容以 UTF-8 原样传递。

send_message 默认等待最多 25 秒，把真实对方回信放在 inbox 中返回原发起对话。没有收到时明确返回 awaiting_reply，发起 Agent 继续 read_messages 长轮询，避免只发不收。等待不替双方决定结束，也不会把普通最终输出冒充对方回信。

新对话默认了解桥的用途和四个工具。当前已安装的三款编码 Agent 配置原生接入；Ollama 是模型运行器，不具备独立 Agent 对话和文件操作接口。未知软件仍需开发真实适配器，不能靠扫描或提示词保证接入。当前 Codex 对话中的 MCP 工具列表不会因改配置而立即重载，仍可用原生 EXE 工具接口。

左右两侧怎么看？

  • 发送方：显示“自己 → 对方”、消息内容与投递状态。
  • 接收方：实际收到后显示“来自对方”和同一条消息。
  • PENDING：排队，尚不能当作收到。
  • DELIVERED：目标会话已通过读消息工具或原生 Adapter 回执确认收到。
  • PROCESSED：目标 Adapter 的该次投递处理已结束；不表示工作完成。
  • FAILED：显示真实错误，不能当作成功。已收到但后续发生错误的内容仍可在两侧看到。

每侧标题下显示真实原生 Session ID。当前发起端保持原会话；桥不会另建一个发起端替身。双方是否发消息、发什么、怎样分工、何时结束，全部由 Agent 决定。

本版本连接能力

本版目标必须能打开其原桌面软件中的真实对话。DSH 使用原桌面服务；Codex 使用持久化原生 thread 和官方指定会话入口。每个连接只在首条消息提交后打开一次，后续消息复用，断开后建立新连接才再次打开。

Claude Code、Gemini CLI、Qwen Code、Kimi CLI 的通信源码保留，但缺少已验证的原桌面对话接口，按用户选择暂时禁止作为目标。检测到安装不等于可以联系。Ollama 只识别安装，未适配目标会话。

A 是已经在使用的原 Agent 会话，不创建替身。B 的原桌面窗口必须对应真实 native_session_id，不能使用桥内视图、终端或新空聊天代替。

找不到目标 Agent

  1. 先打开原 Agent，确认已经登录并能正常工作。
  2. 点击“重新检测”。
  3. 仍找不到现有 Adapter 的入口时，点击“路径设置”。DeepSeek 需要安装桌面版并能正常打开原生窗口；其运行入口为官方 resources/runtime/cli/bin/dsh.cmd，自动检测还需要找到对应的 DeepSeek Harness.exe；Codex 选择官方命令行 codex.exe / codex.cmd。
  4. 保存后重新检测。Claude、Gemini、Qwen、Kimi 分别选择原厂 claude / gemini / qwen / kimi 的 exe、cmd 或 bat 入口。连接期间先点击“断开连接”，再修改入口，无需重启。

不需要在 AgentPhone 填密码或 API Key。DSH 连接只读取已有的本机桌面连接授权，不修改登录文件、模型配置或软件安装目录。如果 DSH 提示权限问题，由原软件显示；桥不代替你批准操作。

给 Agent 的接入说明

窗口底部显示本机 MCP 地址。桥保留 get_agents、send_message、read_messages，以及底层回看需要的 get_conversation。没有任务、项目、分工或验收工具。

首次发送：提供 sender、recipient、content 和当前发起端的真实 sender_session_id。返回 conversation_id；后续发送和读取使用它。读取时提供自己的 Agent ID、相同会话 ID，并使用 after_message_id 游标避免重复。新消息不填回复父 ID；回复可填原消息 ID。

当前 Codex 不必重新启动：可直接使用 EXE 同名工具模式。传入工具参数 JSON，结果写入指定 JSON 文件。没有提供会话 ID 时，工具模式读取当前 Codex 进程继承的真实 CODEX_THREAD_ID；其他 Agent 必须提供自己的真实原生会话 ID，不会随机生成替代会话。

AgentPhone.exe --data-dir 数据目录 --tool send_message
  --request 参数.json --response 结果.json

上面是 Agent 的工具调用方式，普通用户只需在原 Agent 中提需求。使用工具不会打开新的发起端或调用发起端模型。按用户本次要求，默认启动会为已安装的 Codex、DeepSeek Harness、Claude Code、WorkBuddy 配置原生全局使用说明和 MCP 接口；保留其他设置并在本机 ConfigBackups 备份修改前文件。新对话会自动认识这座桥。Claude 和 WorkBuddy 同时通过原生启动事件获知自己的真实会话 ID。部分软件需要重开应用才能重新加载 MCP 配置。

换对话或续接：不用重启

  1. 等当前消息收发结束，点击“选择两边对话”。
  2. A、B 分别选择 Agent，再选“已有对话”或“新对话”，点击“应用对话选择”。
  3. 回到所选 A 的原软件对话中提需求，让它通过桥发信。

只是暂时断联时，点击“断开连接”；原对话和通信记录继续显示。要恢复，点击“续接原对话”，或重新选回同一对已有对话。续接保持原连接和上下文，不自动重跑失败任务。更换端点会停止旧路由；不能让另一个原对话借用旧身份。

Agent 也可用 new_connection: true 联系另一个可联系目标，不携带旧连接或回复 ID；如果桥已有指定选择，仍须遵守所选 A/B。缺少原桌面接口的目标继续禁用。

如何使用其他厂商 Agent

先在原厂软件安装、登录，并能正常工作。只有检测卡片显示“可联系”的目标才可以连接。

当前 DSH、Codex 和 WorkBuddy 已接入原桌面对话入口。Claude Code、Gemini CLI、Qwen Code、Kimi CLI 缺少已验证的原桌面对话接口，按用户选择暂时禁止作为目标。选择 CLI 路径不能绕过限制；终端窗口和桥内双栏不能冒充原桌面对话。

本版不提供任意软件添加向导。开发者须按《Adapter开发说明》同时实现真实通信与原桌面会话入口，通过验证后才解除对应目标限制。桥本机运行，云端 Agent 仍使用自己的网络、账户与额度；桥不代批原 Agent 的操作。

本机运行与断开

软件和消息记录在本机，默认目录 %LOCALAPPDATA%\AgentPhone\ABBridge；模型是否联网由原 Agent 的模型配置决定。开发验证可以指定独立数据目录。

关闭桥会停止桥的投递及它自己管理的目标运行进程，未投递成功的发往目标端的消息记为失败；已经生成、尚未被原发起对话读取的回信会保留，重启后只有原发起会话可继续读取。暂停原连接保留未读回信；更换到另一对端点会停止旧路由。原 DSH / WorkBuddy 桌面软件、对话和正在执行的工作由原软件管理；桥不会关闭原 DSH，也不会发送取消命令。DSH、Codex 和 WorkBuddy 可以恢复同一保存的原对话，两边身份和上下文保留；原生对话丢失时明确报错。

窗口的对话选择仅用于接入原软件；没有桥自己的聊天历史管理、聊天导出、轮次控制或任务输入。内部 SQLite 仅保存通信与排错记录，不是项目管理。AgentPhone 只显示双方显式传递的消息；DSH 原生界面仍按它自己的方式显示会话、工具和工作过程。

连接 WorkBuddy：点选四步

  1. 先正常安装、登录腾讯 WorkBuddy，并能在原软件工作。
  2. 双击桌面 AgentPhone，等检测到 WorkBuddy。
  3. 点“选择两边对话”，在 A 或 B 选择 WorkBuddy，再选择“已有对话”或“新对话”，点击应用。
  4. 回到所选 A 的原对话提出需求。桥自动把显式消息送进对应 WorkBuddy 原对话；首条打开窗口，后续复用。

首次安装适配扩展后，如果 WorkBuddy 已在运行，请等它做完当前任务，从“关于 → 退出 WorkBuddy”正常退出后重新打开一次。之后换 Agent、断开和续接无需重启 AgentPhone。

断联后点“续接原对话”，原会话、上下文和名称不变。桥没有整轮工作倒计时，不取消 WorkBuddy 正在执行的任务。登录、余额和权限请求在原 WorkBuddy 处理。

连接扩展只处理本机原生对话，不代批权限、不读取或转发隐藏思考。WorkBuddyAI 是另一款程序，不自动替代腾讯 WorkBuddy。配置修改前自动备份；扩展缺失或原桌面入口不匹配时会明确报错。
